# Test Plan Summary (Phase 1 Application Ready)

**Project:** MSS-ORU — Modular Sensing Skin ORU  
**Approach:** Simulation-first, then breadboard, interface fit, environmental (Phase 2/3)  
**Interfaces:** CrossLink grapple + iSSI install (D-01)  
**Resources:** Design mass ≤12.5 kg official (≈11.1 kg with margin); MONITOR ~28 W avg; peak ≤65 W; iSSI continuous ≤72 W

---

## 1. Objectives

1. Show FFR-compatible robotic manipulation is **essential** and feasible under stated assumptions.  
2. Verify sensing (visual, thermal, vibration) + edge physical-AI products with explainability.  
3. Demonstrate graceful degradation.  
4. Keep mass/power inside team ceilings pending official FFR confirmation.

---

## 2. Verification philosophy

| Layer | What | When |
|-------|------|------|
| Analysis | Budgets, radiation approach, hazards | Phase 1 |
| Digital twin / SIL | SIM-01…07 sequences, anomalies, FDIR | Phase 1 (now) |
| Breadboard | Sensors + edge compute power/accuracy | Early Phase 2 |
| Mechanical fit | 3D-print / plate CrossLink + iSSI | Phase 2 |
| Environmental | Vibe, TVAC, EMI as required | Phase 2–3 |
| Flight | FDM metrics on orbit | Flight |

## 4. Hardware & analysis path (post Phase 1)

1. **Power measurement** on representative compute + sensors vs 28 W / 65 W.  
2. **Interface fit** to published CrossLink and iSSI drawings (adapter margin).  
3. **Anomaly dataset** from lab shaker + thermal plate + visual defects → TPR/FPR targets (e.g. ≥0.8 TPR @ ≤0.1 FPR).  
4. **Fault injection** on hardware for FR-08.  
5. **Safety review** with flight provider when assigned.

---

## 5. Success metrics (test-linked)

- All SIM-01…07 pass under baselined assumptions.  
- Mass ≤ 12.5 kg official (design ≈11.1 kg with margin).  
- Peak power ≤ 80 W; MONITOR avg ≤ 40 W.  
- Explainable anomaly products schema validated.  
- Degraded mode with ≥1 channel removed.

---

## 6. Assumptions affecting tests

Unknown arm DH parameters, host power pins, downlink, and orbit duration are parameterized (see twin `config.py` and `10_BUDGETS.md`). Designs and demos remain valid if assumptions shift within documented fallbacks.
